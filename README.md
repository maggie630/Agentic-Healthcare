# Agentic Healthcare — Hospital Database & Patient Store

Standalone implementation of MEGHANA's assigned lane for the **Agentic Healthcare Digital Transformation Assistant** capstone.

> **Integration status:** This package was built without access to the original private repository. It is independently runnable and integration-ready, but it has not been merged with or verified against `AKAASH297/agentic-healthcare-assistant`. `data/SCHEMA.md` is a proposal until AKAASH approves it.

## Scope

- SQLite database: `patients`, `records`, `appointments`
- Field-by-field data dictionary and ownership assumptions
- Synthetic demo data and optional Synthea CSV import
- MCP tools: `get_patient`, `search_patients`, `save_record_draft`, `approve_record`
- Human approval gate for draft records
- Tests and Windows setup documentation

Out of scope: policy RAG, image digitization, diagnosis/treatment/medication decision logic, frontend, LLM integration, production identity management.

## Requirements

Python 3.11+ recommended. Dependencies are pinned in `requirements.txt`.

## Quick start (PowerShell)

```powershell
cd Agentic_Healthcare_Standalone
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
pip install -e .
Copy-Item .env.example .env
python scripts/init_db.py
python scripts/seed_db.py --demo
pytest -q
python -m patient_store.server
```

The MCP server uses Streamable HTTP on `127.0.0.1:3001` by default. This is a local development configuration, not a production deployment. Configure a compatible MCP client to connect to `http://127.0.0.1:3001/mcp` (confirm the endpoint against the installed SDK version/client instructions).

## Approval security

Set a non-empty `APPROVAL_TOKEN` in `.env` before using the `approve_record` tool. The caller must supply that token and an approver identifier. The token is a local demonstration gate only; it is not a substitute for production identity, role-based access control, audit infrastructure, or secret rotation. Never commit `.env`.

## Synthetic data only

Use the included clearly labelled synthetic demo data or exports generated by MITRE Synthea. For a Synthea CSV folder, run `python scripts/seed_db.py --synthea-dir path\to\output\csv --max-patients 200`; patients are imported with matching encounters as appointments and conditions/medications as draft chart-context records when those files are present. Never load real patient data. `data/hospital.db`, `.env`, model/cache files, and virtual environments are ignored by Git.
